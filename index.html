Privacy that is not optional

Every property below is enforced by cryptography at the protocol level — not by policy, not by a trusted third party.

🕶️

Stealth addresses

Every payment creates a fresh one-time destination key. Outputs cannot be linked back to your wallet — not even by the sender.

P = Hs(r·A)·G + B
🎭

Ring signatures

Each spend is mixed with decoy outputs from the chain. Observers can prove someone in the ring authorised it — but not who.

sπ = α − cπ·x
🙈

Confidential amounts

Amounts live inside Pedersen commitments. Nodes verify the balance equation homomorphically without ever seeing a number.

C = v·G + m·H
✨

Zero-knowledge range proofs

Every output proves 0 ≤ v < 2³² without revealing v — negative amounts and money-printing are mathematically impossible.

Σ 2i·Ci − C = δ·H
⚡

Lightning instant

Open a channel once (one block), then pay in ~40 ms with no block waits. Cooperative closes settle final balances back on-chain.

state(n+1) requires siga AND sigb
🪙

50M hard cap

Exactly 50,000,000 DCC will ever exist. Subsidy starts at 120 DCC per block and halves every 210,000 blocks — auditable by anyone.

min(120 ≫ ⌊h / 210,000⌋, cap − Σ)

How it works

A CryptoNote-style core with an off-chain Lightning layer — the whole node is pure Python with zero dependencies.

   (view-key scan · spend-key sign)

            │       + one-time stealth outputs
            ▼
  ┌───── consensus / validation ─────┐
  │ PoW blocks · mempool             │

On-chain: private settlement

  1. The sender mixes the real input into a ring of decoy outputs
  2. Amounts are hidden in Pedersen commitments; each output pays a one-time stealth address
  3. Range proofs certify the amounts are positive; ring signatures certify ownership; key images prevent double-spends
  4. Nodes check that the commitments balance — without seeing a single amount

Off-chain: instant payments

  1. Two wallets lock funds in a 2-of-2 channel output on-chain (one block)
  2. Payments exchange signed state updates — both Schnorr signatures, ~40 ms, zero mining
  3. A cooperative close spends the funding output and pays each side its final balance
